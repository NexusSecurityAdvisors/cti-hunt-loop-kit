## 1. Intelligence basis

PowerShell remains one of the most heavily abused execution techniques across ransomware affiliates, initial-access brokers, and state-sponsored actors. Common tradecraft includes:

- Base64-encoded commands passed with `-EncodedCommand` (or abbreviations such as `-enc`, `-e`, `-ec`) to hide intent from casual review.
- "Download cradles" that fetch and execute a remote payload in memory (`IEX (New-Object Net.WebClient).DownloadString(...)`, `Invoke-WebRequest`, `Start-BitsTransfer`).
- Execution spawned from unusual parents: Office applications, `wmiprvse.exe`, `mshta.exe`, `rundll32.exe`, or web server processes.

Map this to your own PIRs by citing the specific report or advisory in your hypothesis card.

## 2. Hypothesis

> If an adversary is using PowerShell for execution or payload delivery in our Windows estate, we expect to see `powershell.exe` / `pwsh.exe` process-creation events with **encoded command arguments** or **download-cradle keywords**, especially from **unusual parent processes or user contexts**, in endpoint process telemetry during the last 14–30 days.

**Refuted if:** process-creation telemetry covers ≥ 90% of in-scope hosts for the window and all hits are attributed to known, documented benign sources.

## 3. Data sources

| Source | Event / table | Key fields |
|---|---|---|
| Sysmon | Event ID 1 (Process Create) | `Image`, `CommandLine`, `ParentImage`, `User` |
| Windows Security | Event ID 4688 (requires command-line auditing enabled) | `NewProcessName`, `CommandLine`, `ParentProcessName` |
| Microsoft Defender XDR | `DeviceProcessEvents` | `FileName`, `ProcessCommandLine`, `InitiatingProcessFileName` |
| PowerShell Operational | Event ID 4104 (Script Block Logging) | `ScriptBlockText` — shows decoded content |

**Pre-check:** confirm command-line capture is enabled. Without it, 4688 events will not support this hunt and the outcome should be logged as **Inconclusive (data gap)**.

## 4. Hunt steps

1. **Run the query** for your platform across the hunt window.
2. **Stack by parent process.** Sort by `count` ascending — rare parents (Office apps, script hosts, web servers, `wmiprvse.exe`) are the highest-value leads.
3. **Decode the payload.** PowerShell `-EncodedCommand` uses Base64 over **UTF-16LE**:
   ```powershell
   [System.Text.Encoding]::Unicode.GetString([Convert]::FromBase64String("<blob>"))
   ```
   The KQL query attempts this automatically; otherwise decode in CyberChef (*From Base64 → Decode text: UTF-16LE*).
4. **Pivot** on suspicious hits:
   - Network connections from the same process / host in the minutes afterward (proxy, DNS, `DeviceNetworkEvents`).
   - Files written (`DeviceFileEvents`, Sysmon 11), especially in `%TEMP%`, `%APPDATA%`, `C:\ProgramData`.
   - Script block logs (4104) for the full deobfuscated script.
   - Same command line on other hosts (spread / automation).
5. **Classify** each cluster as malicious, suspicious, or benign and record it in the hunt report.

## 5. Known benign sources (tune, don't ignore)

| Source | How to recognize |
|---|---|
| SCCM / Intune / RMM agents | Parent is the management agent; consistent command line across many hosts |
| Vendor installers & updaters | Signed parent binary, runs at install / update time |
| Admin scripts & scheduled tasks | Service account context, regular schedule, documented in change records |
| Security tooling | EDR or vulnerability scanner parent process |

Document each confirmed benign source so it can become a scoped exclusion in the production detection — never a blanket exclusion of `powershell.exe`.

## 6. Triage questions

- Is the parent process expected to launch PowerShell at all?
- Is the user context interactive, service, or SYSTEM? Does that fit the host role?
- Does the decoded content reach out to an external URL or IP? Is the destination known?
- Is the same command line present on one host (targeted) or hundreds (likely tooling)?
- Did anything new persist (scheduled task, Run key, service) shortly after?

## 7. Operationalize

- Promote the Sigma rule to production after tuning exclusions from step 5.
- Recommend enabling **Script Block Logging (4104)** and **Module Logging** if not already on.
- Recommend **Constrained Language Mode** / application control (WDAC, AppLocker) for non-admin users where feasible.
- Record outcome, detections created, and data gaps in `templates/hunt-report.md` and `templates/intel-feedback.md`.
